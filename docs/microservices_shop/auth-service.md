# Auth Service

Auth Service регистрирует пользователей, проверяет пароль при входе и выдаёт JWT. Он хранит данные в таблице `users`. API Gateway принимает токен в последующих запросах к защищённым маршрутам.

## Маршруты регистрации и входа

| Операция | Внешний путь через gateway | Внутренний путь Auth Service | Успешный ответ |
|---|---|---|---|
| Регистрация | `POST /api/auth/register` | `POST /register` | `201` |
| Вход | `POST /api/auth/login` | `POST /login` | `200` |

Оба запроса принимают `email` и `password`. Email должен иметь допустимый формат. Длина пароля — от 8 до 128 символов.

При регистрации Auth Service проверяет email, хеширует пароль, сохраняет пользователя и выдаёт токен. При входе он находит пользователя по email, сверяет пароль с сохранённым хешем и выдаёт токен.

## Данные пользователя и ответ с токеном

В БД у пользователя есть `id` (UUID в виде строки), `email` с ограничением уникальности, `hashed_password` и `created_at`. Регистрация и вход возвращают одни и те же поля.

- `access_token` — подписанный JWT.
- `token_type` — `bearer`.
- `user` — объект с `id` и `email`.

В JWT записываются `user_id`, `email`, `role` со значением `user` и срок действия `exp`. Клиент передаёт токен в `Authorization: Bearer <access_token>`. Маршрут `GET /api/auth/me` реализован в API Gateway и возвращает `id` и `email` из проверенного JWT.

## Ошибки регистрации и входа

| Ситуация | Статус Auth Service | Сообщение |
|---|---|---|
| Email уже зарегистрирован | `400` | `Email already registered` |
| Пользователь с таким email не найден при входе | `400` | `User doesn't exist` |
| Пароль не совпадает | `401` | Стандартный ответ об ошибке авторизации |
| Некорректное тело запроса | `422` | Ошибка валидации |
