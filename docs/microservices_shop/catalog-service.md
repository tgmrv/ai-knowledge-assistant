# Catalog Service

Catalog Service хранит товары в таблице `products`. API Gateway использует каталог для отображения товаров, а Order Service запрашивает товар по ID, чтобы получить название и цену при создании заказа.

## Маршруты каталога

| Внутренний путь Catalog Service | Внешний путь через gateway | Результат |
|---|---|---|
| `GET /products` | `GET /api/products` | `200`, список товаров по возрастанию имени. Если товаров нет, возвращается пустой список. |
| `GET /products/{product_id}` | `GET /api/products/{product_id}` | `200` с товаром или `404`, если товар отсутствует. |
| `POST /products` | — | `201`, созданный товар. |
| `DELETE /products/{product_id}` | — | `204` без тела при удалении существующего товара. |

Для внутреннего `GET /products/{product_id}` ответ при отсутствии товара содержит `detail: "Product not found"`. Обработчик удаления работает с существующим товаром и отдельно не проверяет случай отсутствующего ID.

## Поля товара

| Поле | Тип и назначение |
|---|---|
| `id` | UUID в виде строки. Сервис генерирует ID при создании и возвращает его в ответе. |
| `name` | Обязательная строка с названием товара. |
| `category` | Обязательная строка с категорией. |
| `price` | Обязательное число, в коде используется `float`. |
| `description` | Необязательное описание, по умолчанию `null`. |
| `image_url` | Необязательная строка с адресом изображения, по умолчанию `null`. |

## Как добавить товар для демонстрации

Для наполнения каталога используется внутренний `POST /products` Catalog Service. Внешние маршруты gateway дают доступ к чтению каталога. В примере запроса создаётся товар с ценой 1400.

```json
{
  "name": "Демонстрационный товар",
  "category": "demo",
  "price": 1400.0
}
```

В ответе нужно взять поле `id` и передать его как `product_id` в позиции заказа. Order Service сохранит название и цену товара на момент создания заказа.
